## 2. 本番で保護が効いていることの確認

未ログインの状態で、保護された画面が開けないことを確かめる。

```bash
for p in / /login /reset-password /applications /applications/new /applications/history /admin /applications/export; do printf "%-28s %s\n" "$p" "$(curl -sS -o /dev/null -w '%{http_code}' https://apply-tracker-self.vercel.app$p)"; done
```

**期待する結果**

| パス | コード |
|---|---|
| `/login` `/reset-password` | **200** |
| それ以外（`/` `/applications` `/admin` `/applications/export` など） | **307**（ログイン画面へ転送） |

とくに `/applications/export` が 307 であること。ここが200でデータが返ったら重大な欠陥。

## 4. 管理者キーが公開されていないことの確認

配信されているJavaScriptを全部集めて、秘密の値を探す。

```bash
B=https://apply-tracker-self.vercel.app
H=$(curl -sSL $B/login)
ALL="$H"
for c in $(echo "$H" | grep -oE '/_next/static/[^"]+\.js' | sort -u); do ALL="$ALL$(curl -sS $B$c)"; done
echo "取得バイト数: $(printf %s "$ALL" | wc -c)"
for n in sb_secret_ SUPABASE_SERVICE_ROLE_KEY service_role; do printf %s "$ALL" | grep -q "$n" && echo "NG $n が含まれる" || echo "OK $n は含まれない"; done
```

**期待する結果**: 3つとも「OK」。1つでもNGなら、**直ちにSupabaseでキーを再発行すること。**
