# 引き渡し手順

- 対象: ApplyTracker
- 作成日: 2026-08-31

**このアプリは3つのサービスの上で動いている。**
発注者に引き渡すときは、3つとも権限を移す必要がある。
どれか1つでも残っていると、制作者がいなくなった時点で運用できなくなる。

## 全体の構成

```
GitHub          ソースコードの置き場所。CIもここで動く
   │  コードを送ると自動で反映
   ▼
Vercel          画面を配信する場所（本番URL）
   │  データの読み書き
   ▼
Supabase        データベースとログイン機能
```

## 1. GitHub

1. リポジトリの **Settings → Collaborators and teams**
2. 発注者のGitHubアカウントを **Admin** 権限で招待
3. 発注者が承諾したら **Settings → General → Transfer ownership** で所有権を移す
4. **Settings → Secrets and variables → Actions** に登録されているキーを、発注者が入れ直す
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`

## 2. Vercel

1. プロジェクトの **Settings → General → Transfer**
2. 発注者のアカウント（またはチーム）へ移す
3. 移した後、**Settings → Environment Variables** に上と同じ3つが入っているか確認
4. 発注者側で一度 **Redeploy** して、正常に動くことを確認

## 3. Supabase

1. **Settings → General → Organization** から、発注者を **Owner** として招待
2. 発注者が承諾したら、制作者のアカウントを外す
3. **Authentication → URL Configuration** の Site URL と Redirect URLs が
   本番URLになっていることを確認

## 4. 引き渡し後の確認（発注者が行う）

| # | 確認 | 済 |
|---|---|---|
| 1 | 本番URLが開ける | |
| 2 | 自分のアカウントでログインできる | |
| 3 | 案件を1件登録できる | |
| 4 | GitHubにコードを送るとCIが動く | |
| 5 | Vercelが自動で新しい版を公開する | |
| 6 | Supabaseの管理画面に入れる | |

## 5. 制作者側でやること（引き渡し完了後）

- 手元の `.env.local` を削除する
- Supabase / Vercel / GitHub から自分のアクセスを外す
- **service_role キーを再発行してもらう**（制作者が値を知っているため）
  - Supabase → Settings → API Keys から再生成
  - 再生成したら、GitHub Secrets と Vercel の環境変数も更新が必要

**この最後の項目を忘れると、辞めた後も制作者が全データにアクセスできる状態が残る。**

## 6. 保守について（着手前に合意しておく）

| | 対応 | 費用 |
|---|---|---|
| 検収前に見つかった仕様との不一致 | 無償で修正 | なし |
| 検収後の不具合（契約不適合責任の期間内） | 無償で修正 | なし |
| 検収後の仕様変更・機能追加 | 別途見積り | 有償 |
| 運用中の問い合わせ対応・監視 | 保守契約の範囲 | 月額または時間単価 |

期間と範囲は契約書に明記すること。
